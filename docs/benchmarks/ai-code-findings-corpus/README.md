# AI-Code Findings Corpus

A reproducible corpus study measuring how often BrassCoders emits a finding on
naturally-generated (un-planted) AI Python code. Companion to the planted-bug
benchmark in `../ai-coder-bugs/` — that one measures *recall on known bugs*; this
one measures *finding rate in the wild*.

## Pre-registration (committed BEFORE running the scan)

**Date:** 2026-06-29

**What we measure:** the share of corpus files for which `brasscoders --offline scan`
emits at least one finding, plus the breakdown of findings by scanner category.

**What this is NOT:** a confirmed-bug rate. BrassCoders is a deterministic pattern
reporter; its raw findings include false positives by design (the AI consumer —
Claude/Cursor — triages them). So the headline metric is **"% of files with ≥1
finding flagged for review,"** never "% of files with bugs." The post must use that
language.

**Corpus construction:**
- Files are natural solutions to realistic Python coding prompts, generated by an AI
  assistant (Claude Opus 4.8, June 2026), answering each prompt at normal effort with
  NO attempt to plant or avoid issues. This is a single-model corpus; that is a stated
  limitation, not a hidden one.
- Each file carries a `PROVENANCE` docstring naming the exact prompt + model + date.
- Prompts target realistic tasks where finding rates are worth knowing (I/O, web
  handlers, data processing, subprocess, auth, config). The prompt list is fixed in
  `manifest.json` before scanning.

**Scoring (fixed before run):**
- Run `brasscoders --offline scan` on the corpus directory.
- `files_with_findings / total_files` = headline rate.
- Per-category counts come straight from scanner output; no manual reclassification.
- No file is added or removed after the first scan. If a file fails to scan, it is
  reported as such, not dropped.

**Reproduce:**
```bash
pip install brasscoders
brasscoders --offline scan path/to/ai-code-findings-corpus/files
```

## Honesty notes carried into the blog post
- Report findings, not "bugs."
- State the single-model limitation.
- Distinguish structural findings (deterministic, high-confidence: hallucinated
  imports, secrets, perf anti-patterns) from pattern flags that need triage.
